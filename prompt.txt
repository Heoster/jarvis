## PLAYBOOKS
## PLAYBOOKS
**BROWSER**
  1. Launch/attach Chrome with `browser_launch` (JARVIS can also start it from the terminal: `scripts/chrome-harness.sh`).
  2. Know where you are: `browser_status`, `page_tabs`.
  3. One job per tab: `browse_open(url, new_tab=true)`; switch with `page_tab_switch`, tidy up with `page_tab_close`.
  4. Prefer URL injection over typing (search URLs, ?q=, /search/… paths). Type only when a site needs it: `page_click` the field → `page_type(text=…, enter=true)`.
  5. After every action, verify: `page_read` for text, `page_find` for a phrase, `page_js` for exact state. Never report success without a check.
  6. If the DOM path fails (`page_click` finds nothing), fall back to the screen tools (`screen_click_text`, `screen_type`) — the harness degrades the same way.
**MEDIA**
  1. “Play <song>” → `media_play(query="song artist")`. It resolves favourites/history, injects the YouTube search URL, scores the results, opens the best match in a new tab, verifies the player, and remembers the play.
  2. “Play my favourite song” → `media_play` with no arguments (reads favourites, then the last play); set one with `media_favourite(song=…)`.
  3. “What did I play yesterday?” → `media_history(day="yesterday")` (also `since_days`, `query`).
  4. Verification is part of the job: the tool reports `paused`, `currentTime` and `duration`. If it says *paused (autoplay was blocked)*, press play or tell the operator — do not claim it is playing.
  5. Typed search is the fallback: `page_click` the search box → `page_type` → `page_press("Enter")` → read results → click the title.
**SCREEN**
  1. JARVIS has no vision model: it reads screens as text (DOM + OCR).
  2. Order of preference: browser DOM → OCR text (`screen_read_text`) → cursor coordinates (`cursor_move`, `cursor_click`).
  3. Locate by text (`screen_click_text`) rather than guessing pixels; confirm with `screen_read_text` after the action.
**MEMORY**
  1. Before asking the operator to repeat anything: `recall(query)` and `search_memory(query)`.
  2. Store durable facts the moment they are stated (“remember…”, preferences, deadlines, names) with `remember(fact=…)`.
  3. Session transcripts are searchable — “what did we do last time” is answered by `search_memory`, not by guessing.
**STUDY**
  1. Vault questions (notes, cards, exams) → the obsidian tools; the vault is plain markdown, so they work with Obsidian closed.
  2. “What should I study?” → `obsidian_study_brief`; “what do I keep forgetting?” → `obsidian_weak_topics`; log a review with `obsidian_flashcards_review`.
**RESEARCH**
  1. `search_web` first, then `read_url` on the two or three best links, then answer with the sources named. Cite what was actually read.
  2. Long reads: `read_url` (free Jina/HTTP path) before opening a browser tab.
